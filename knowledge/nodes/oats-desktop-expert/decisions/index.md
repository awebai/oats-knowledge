# Decisions

Product, design and security decisions with their rationale and rejected alternatives. Each names its acceptance date; supersession is recorded in place.

* [A team view names your instances, not the team's full membership](team-instance-lists-state-their-observation-scope.md) - Label team instance lists and counts as the user's observed deployments and state their machine scope, so a partial view never implies a complete team roster.
* [Desktop chrome uses sans names and role-based type hierarchy](chrome-typography-follows-information-role.md) - Give primary names foreground sans at weight 600 and reserve monospace for secondary machine strings, using a short size-and-weight hierarchy instead of extra colours or uppercase labels.
* [Explain a technical model with an overview and a closed developer disclosure](technical-models-use-overview-and-developer-disclosure.md) - Lead with one plain user-facing sentence and place developer-only mechanisms in a native disclosure, sharing state meanings with the visible rows rather than maintaining a second explanation.
* [A filtered roster answer must not erase groups it did not ask about](filtered-roster-preserves-unasked-groups.md) - Narrow roster replacement to the requested workspace scope while retaining unasked groups as old observations, so filtering cannot forget machines or erase the route back to another workspace.
* [An unreached host keeps Stop and Retire available through a fresh plan](unreached-host-actions-use-the-plan.md) - Keep unknown remote rows actionable through the kernel's routed plan rather than hide Stop and Retire on the strength of an earlier failed roster read.
* [Shared readers separate client terms from attributed kernel prose](shared-readers-separate-client-terms-and-kernel-prose.md) - Share facts and code meanings, require explicit client terms, keep control-specific next steps in a closed code set worded by each client, and return attributed kernel prose as separate parts.
* [Shared terminal opening keeps invocation context and client scope](shared-terminal-opening-keeps-context-and-client-scope.md) - Interpret attach outcomes with the facts that give them meaning, add a client-specific action without changing another client's menu, and preserve both kernel refusal texts.
* [A client probe must not turn kernel unknown into a confident state](kernel-unknown-is-not-refined-by-a-client-probe.md) - Preserve a kernel-unknown row and its recorded session facts rather than manufacture liveness or terminal eligibility from a weaker client probe.
* [Remove wording needs an owned-worktree fact, not a mode or default](remove-wording-needs-an-owned-worktree-fact.md) - Base Remove's worktree promises on the kernel's explicit ownership fact because a recorded work mode and a retention default do not establish what belongs to the instance.

* [One standalone Desktop product, no hidden operational kernel](standalone-product-and-cli-authority.md) - The installed CLI is the model Desktop renders and the only way it changes a deployment.
* [Manual execution keeps CLI authority and requires an informed press](informed-manual-actions-match-cli-authority.md) - When a Desktop verb gains an execution effect, preserve the CLI's manual-action authority and map informed confirmation to the kernel's explicit intent flag rather than adding a trust gate.
* [Source-supplied prose is an attributed quote, not Desktop's voice](source-prose-is-an-attributed-quote.md) - Display prose from trigger sources, trigger files and capability manifests as visibly attributed text so untrusted words cannot impersonate Desktop's own explanation.
* [Shared Desktop code keeps one relative path in the repository and package](shared-code-keeps-one-relative-path.md) - Preserve one source and one relative import path for shared client code, avoiding stale generated copies while making packaging boundaries explicit and testable.
* [The loopback interface is Desktop's trust boundary](loopback-trust-boundary-and-transport-simplicity.md) - Loopback-only bind with Host and Origin guards, because the backend types into agent terminals.
* [Agent-centered navigation makes the action target legible](agent-centered-navigation.md) - A stable roster and one authoritative inspection flow keep artifacts contextual and launch intent explicit.
* [Closed panels return their space to the main area](closed-panels-return-main-area-space.md) - Closing a sidebar or instance panel removes its entire footprint, and instance selection must not undo the user's choice to keep the panel closed.
* [Terminal tabs are viewers, not session owners](terminal-viewers-not-session-owners.md) - Exact-source terminal viewers preserve native interaction and atomic redraws without owning durable sessions, changing other clients or silently switching agents.
* [Workspace admission is privileged and transactional](privileged-workspace-admission.md) - Workspaces are admitted only from validated sources, after identity and readiness are established.
* [The bundled server ends with its app owner, without interrupting CLI children](bundled-server-owner-lifetime.md) - An owner-only stdin pipe bounds the bundled server's lifetime across app crashes without claiming authority over another app's server or in-flight CLI work.
* [Spawn deadlines follow the confirmed preview, not the request lifetime](preview-bounded-spawn-outcomes.md) - Bind spawn work to the confirmed preview, isolate it from client hang-up, and use bounded targeted observation without weakening deadlines or typed compensation outcomes.
* [Editor groups own layout and close succession](editor-group-layout-ownership.md) - Persistent groups, not per-tab split slots, own ordered work and focus.
* [One design authority, a stated quality bar, and a native terminal](design-direction-and-quality-bar.md) - The expert owns UX and design direction and the developer implements it; the terminal keeps native geometry.
* [Calibrate terminal stroke weight per theme without changing cell geometry](per-theme-terminal-stroke-weight.md) - Theme-specific stroke weight matches the native terminal reference without changing cell geometry or adding a user setting.
* [Explicit sibling links are shown on both ends and apart from parentage](sibling-relations-are-shown-apart-from-parentage.md) - Show only direct explicit sibling links on both endpoints, using words in the palette and a separate meaningful dotted line in the sidebar so siblinghood cannot be mistaken for parentage.
* [Name-ordered rosters preserve recognition across state changes](roster-name-order-preserves-recognition.md) - Order roster bundles by their first root rather than liveness or member count, so starts, stops and a first child do not reprioritize the agents the operator is tracking.
* [Needs-input attention preserves liveness and roster recognition](needs-input-preserves-liveness-and-recognition.md) - A separate text-and-icon marker and collapsed-parent roll-up expose waiting agents without overloading liveness, reordering rows or displaying a stale elapsed time.
* [Identity marks show a two-letter abbreviation](two-letter-identity-marks.md) - One roster-independent rule gives every soul, capability and workspace two glyphs; mark stacks overlap by 1px so no letter hides.
* [A soul's page shows its own and its composed AGENTS.md](soul-instructions-own-and-composed.md) - The soul's part is set apart from every injected part; the composed text is an opt-in inspect field, and routed souls gate on the host's own reported features.
