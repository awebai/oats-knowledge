# Lessons

Hook and testing discipline learned building providers against the kernel's contracts.

* [A fake CLI that accepts what the real binary refuses hides a broken hook — a provider hook that drives an external CLI is accepted on a rehearsal, not on its unit tests](a-fake-cli-that-accepts-what-the-real-binary-refuses-hides-a-broken-hook.md) - Unit tests with a fake prove a hook against the fake's contract, not the tool's; the fake must model refusals, resolution rules and output shape, and a hook that talks to an external CLI passes review only with a live-rehearsal record.
* [A lifecycle hook never trusts the ambient environment — hooks inherit the operator's process, and the operator can be another instance](a-lifecycle-hook-never-trusts-the-ambient-environment.md) - Locators, credential homes and teams come from the payload, persisted meta or the instance home, never from the environment; strip what the hook's own tool would misread.
* [A hook reports only the cleanup it confirmed — compensation returns meta for a retry and re-checks an uncertain effect before claiming it](a-hook-reports-only-the-cleanup-it-confirmed.md) - On failure, emit meta, claim only confirmed effects, re-check after a timeout, and keep compensation idempotent from both ends.
* [A merged provider payload cannot enforce host-only keys — the resolver, not the hook, refuses a setting that must come from the host file](a-merged-provider-payload-cannot-enforce-host-only-keys.md) - The hook sees one merged map with no provenance; declare host-only keys in the manifest and let the resolver reject them elsewhere.
* [Capability resources resolve inside the package root — a path that escapes the hashed tree makes the integrity check meaningless](capability-resources-resolve-inside-the-package-root.md) - Manifest-relative paths for hooks, commands, skills and injections resolve beneath the real package root, or the lock's integrity digest never covered the bytes that run.
* [Task integrations document a support matrix — which operations the integration exposes, which are human-only, and where durable information lives](task-integrations-document-a-support-matrix.md) - A command list is not documentation; the matrix and the escalation guardrail make the integration's boundary a fact the agent can read.
* [Prefer a narrow integration-owned wrapper over a third-party CLI — expose only the operations agents need, keep secrets in the environment, surface missing authentication early](prefer-a-narrow-integration-owned-wrapper-over-a-third-party-cli.md) - Own a small JSON-first wrapper over the service's API; credentials from the environment, never committed; an advisory warning plus an actionable auth failure.
* [Settings reach hooks as a payload, and the brief tells the agent where they are — an advisory hook writes the brief and persists meta without calling the service](settings-reach-hooks-as-a-payload-and-the-brief-tells-the-agent-where-they-are.md) - One merged payload in, one brief line and persisted meta out; the skill says where to look and when to stop; advisory hooks warn, required hooks fail.
* [Integration guidance names only verbs the target CLI exposes, and readiness follows the hook's own selection](guidance-names-only-verbs-the-target-cli-exposes.md) - A capability's setup text must be pinned to the real CLI it drives by a test that runs each named verb's help, host-only settings are manifest metadata verified by resolver tests, and a readiness check must resolve the team exactly as the spawn hook does.
* [Type availability failures for the operator, but rethrow domain errors untouched](type-availability-failures-but-rethrow-domain-errors.md) - When a knowledge or messaging provider wraps remote operations to produce typed, operator-friendly availability errors, the wrapper must catch only transport and unusable-source failures and let custody, confirmation, path and validation errors pass through with their original codes.
* [A personal team per workspace needs a service primitive](a-personal-team-per-workspace-needs-a-service-primitive.md) - A personal-workspace team and token-free shared-team joining both require a human CLI login the messaging service does not yet provide; until then the provider exposes setup as a required guided step and never invents local shims.
* [A capability's own manifest overrides guidance prose about what its settings require](capability-manifest-over-guidance-prose.md) - Prose can be stricter than or different from the code, so verify manifest settings and CLI commands before declaring a human block or naming an operator step.
* [A soul declaration that suppresses a default must also provision its replacement, or the instance silently loses both](declared-oats-core-without-activation-yields-skill-less-instance.md) - On the classic path, a soul created with the default core capability requirement stopped receiving the kernel's operational block and skills, but nothing installed or activated the capability; spawn then scaffolded a home with zero skills and no warning.
