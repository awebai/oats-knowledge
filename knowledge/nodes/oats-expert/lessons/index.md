# Lessons

* [Interim docs create migration inputs for the later command](interim-docs-create-migration-inputs.md) - When interim docs teach a manual artifact that a later command will manage, name those copies in the command spec, justify adoption or refusal from their authorship and ownership, and plan the migration text with the command's docs follow-up.
* [Outliving a client requires independent output, not only no signals](outliving-a-client-needs-independent-output.md) - A lifecycle change promised to outlive its client needs output destinations independent of that client's readers, because detachment and a no-signal policy alone leave a broken-pipe failure path.
* [Real-terminal waits must prove the state they observe](real-terminal-waits-prove-the-observed-state.md) - Before trusting a real-terminal content or absence check, establish the intended view and fixture state, account for capture transformations, and wait for a closing transition before sending the next key.
* [Verify host-bound fixes on the reproducing host](verify-host-bound-fixes-on-the-reproducing-host.md) - When the fixing host lacks the runtime that exposes a bug, obtain exact-head evidence on the reproducing host using the same minimal repro and a no-fix control, with harness failures reported separately.
* [Check the affected-test inventory, not only the green runs](check-affected-test-inventory-at-handback.md) - When full suites run only in CI, require a search-derived inventory of test files consuming changed surfaces at handback and check its coverage against the diff, with a result or non-run reason for each file.
* [The spec author rechecks dictated words against the build](recheck-dictated-words-against-the-build.md) - When a spec fixes user-facing wording, the author requests wording discrepancies at handback and checks the sentences against the built cases before the PR opens.
* [Compare a code-reading leaning with alternatives before specifying it](compare-a-leaning-with-alternatives-before-specifying.md) - Before a risky implementation assumption becomes a spec, compare the lead's preferred approach with plausible alternatives under the same state-preservation and interruption checks.
* [Send a relay's own reading to the maintainer before offering a remedy](relay-own-readings-through-the-maintainer.md) - When acting as the OATS contact for an outside adopter, submit your own diagnosis or workaround to the maintainer first and relay only the accepted answer without adding a remedy.
* [Date host-read facts before a cross-workspace adoption gate](date-host-read-facts-before-an-adoption-gate.md) - Before a version-dependent adoption gate, enumerate the adopter's hosts from team presence and require each version to be read on the named host with its observation time and reporting route.
* [A passing composition does not prove every copied input is needed](prove-copied-inputs-are-needed.md) - Before requiring a second client to retain state copied from the first, compare its composition with and without each candidate input and establish which consumer path actually needs it.
* [Run the consumer spec against the built producer before handover](run-consumer-spec-against-built-producer.md) - When a consumer spec predates its shared producer, exercise its compositions against the built code before handing it to the developer; matching names does not establish matching behavior.
* [Establish the cause before changing a restore-test baseline](control-before-changing-a-restore-baseline.md) - Before changing what a restore test compares against to cure a platform-specific failure, use controls to distinguish the program's effect from the harness or environment's effect.
* [Inspect the producer before making a client limitation a permanent exception](inspect-the-producer-before-making-an-exception-permanent.md) - Before declaring a rule exception permanent because a client lacks provenance, inspect the producer that combines the sources and determine whether it can preserve the distinction.
* [Review shared-client prerequisites with their owner before depending on them](import-closure-needs-owner-review.md) - Review shared modules and callers with their owner before estimating a second client, then isolate and test small shared prerequisites for owner review at an exact commit before building their consumers.
* [Test feasibility before committing to a plan](test-feasibility-before-choosing-between-owners.md) - Use bounded, authorized CI spikes to settle feasibility disagreements and recheck inherited limitations before planning hardware, rental or recurring manual work around them.
