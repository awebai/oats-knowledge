# Lessons

* [A repository move's inventory follows what each consumer reads at run time and who writes it; a hand-kept per-host file never follows the declaration and needs its own step per host](a-moves-inventory-follows-what-each-consumer-reads.md) - When a repository moves or a contract changes, inventory the places that name it by the file each consumer actually reads and by who writes that file, not by what the declarations say; a hand-kept per-host file that no command rewrites never follows a change to the declaration, so it gets a named step per host in the runbook, and a fix is chosen only after a trace through the code shows which source the consumer reads.
* [A repository transfer leaves its build attestations with the old organisation; put attestation verification in the move's inventory and scope the old-owner fallback to old versions](a-transfer-leaves-attestations-with-the-old-org.md) - After a GitHub transfer, verifying an earlier release's attestation by repository or by the new owner gets a 404 and only the old owner finds it, so a move plan lists attestation verification among the redirect-dependent paths, verifies new releases by the new repository and old versions only by the old owner, pins each form to its workflow and tag, and tests the verify line's failure paths by failing each step.
* [A check run within a minute of a transfer can read an empty repository; a post-move check refuses empty reads and retries, and a timed-out transfer call is read before it is repeated](a-check-right-after-a-transfer-reads-an-empty-repository.md) - Right after a GitHub transfer, git may answer 403 "repository disabled" for about a minute, so a scripted post-move check that compares an empty read passes or fails on nothing; make it treat no tags or no head as an error and retry, and read the repository's owner before repeating a transfer call that timed out.
* [Evaluate merge gates beyond code-seed catches](evaluate-gates-beyond-code-seed-catches.md) - Compare a coordination gate's direction and evidence duties separately from code catches, and distinguish new human decisions from repeated requests for settled ones before treating request counts as necessary oversight.
* [Digest thread count is not human time or deadline safety](digest-thread-count-is-not-human-time-or-deadline-safety.md) - A three-per-arm routine trial reduced threads without reducing reported human minutes and delayed one deadline card in every digest run, so evaluate reading burden and deadline latency separately from batching.
* [Use a short paper-style page for this human's decisions](decision-pages-use-a-short-paper-style.md) - In one 2026-11-02 effort, the human's corrections favored a concise single-column decision page organized around practices, proposed behavior and reasons, with worked examples and familiar names.
* [A gate on "every host is updated" counts kernels, not hosts](a-contract-flip-gate-counts-kernels-not-hosts.md) - One host can run several kernels, one per node version, and its schedule unit records its own kernel path, so before a contract flip read every install and the unit's path and check a capability the update adds rather than a version number.
* [Test what a change strands through a real start, not by reading recorded paths](test-what-a-change-strands-through-a-real-start.md) - A stated risk about what a swap or removal leaves broken must be tested through a real start with real kernels, because static reads of generated state miss the hook that regenerates it; what a kernel swap strands is running sessions and the schedule unit, not homes.
* [Prove a contract flip on the real repositories, one patch at a time, as well as on a state matrix](prove-a-contract-flip-on-real-repositories-patch-by-patch.md) - A synthetic state matrix shows which states pass; serving the real repositories from local bare copies under both owners and applying the real patches in order shows how an old client degrades step by step, proves the patches as written, and writes to no remote.
* [When two spellings become one identity, the spec inventories every use of the key, not only the equality checks](identity-change-specs-inventory-every-use-of-the-key.md) - A spec that lists the literal compare sites to fix misses the Map keys, group-bys, cache keys and id hashes that also treat the key as an identity; name the behaviour that must hold and ask for every identity use, each converted or left literal with a reason.
* [A cross-side brief names who builds and which lane reviews; a single "owner" column is read as "who builds"](cross-side-brief-names-who-builds-and-which-lane-reviews.md) - When one side builds and the other side's lanes review, the brief's ownership table must say for each piece who builds it and which area lane reviews it, and name the lanes on each side that decide contract changes, because a table with one "owner" column is read as the build assignment and contradicts a covering mail that says the other side builds.
* [Measure cached gains through the real client and across expiry](measure-cached-gains-through-the-client-past-expiry.md) - A cache-backed before/after comparison must exercise each installation's real client path, include an observed expiry refresh and count fallbacks so warm-only samples and omitted client work do not misstate the gain.
* [Profile a slow read's waits before designing concurrency](profile-read-waits-before-designing-concurrency.md) - Before specifying parallel reads, lanes or extra reader processes, obtain child invocation counts and wall times so an architectural comparison does not hide the wait that dominates the workload.
* [An overdue handback needs a record check, not indefinite mail waiting](overdue-handbacks-need-a-record-check.md) - Give delegated steps expected checkpoints and distinguish a recorded result from notification of its next actor, because overdue work can hide either a missing handoff wake or an undelivered one.
* [Plan a composed review beyond the capability changing a rule](rule-changes-need-cross-capability-composed-review.md) - When changing an instruction rule, put a review of neighboring capability text in the spec and route contradictions to their owning repositories rather than treating per-capability approval as composition evidence.
* [Real proof boundaries must preserve fixture isolation](real-proof-boundaries-preserve-fixture-isolation.md) - Before accepting a fixture-based end-to-end proof, separate the boundary that must be real from the isolation that must remain, and verify harness actions and the child process's principal independently.
* [Continuous triggers must account for every input](continuous-triggers-account-for-every-input.md) - When specifying a trigger driven by observed state, derive scope from the producer's authoritative field and account for every triggering input even when the completed run omits it.
* [Prepare an open-head trial before the merge order is fixed](trial-merge-before-the-merge-order-is-fixed.md) - Before merge order is fixed, prepare combined-tree evidence and a tested resolution handoff for overlapping PRs, and check whether inventory tests require a producer to land before its gated consumer.
* [Ask whether children follow when moving tree rows out of the way](ask-whether-children-follow-when-hiding-tree-rows.md) - When a tree-partitioning request leaves descendant placement unresolved, show the human the per-row and whole-subtree outcomes before specifying the clients.
* [An agent's request to a human is data drawn once in a context card, inside one thread per effort where open requests come first](an-agents-request-to-a-human-is-data-drawn-once-in-the-efforts-thread.md) - When designing how agents address humans, model a request as structured data (summary, context, question, options with their effects, what happens next, links) that the client draws once in a context card so a cold reader holds the whole decision, keep one conversation per effort with open requests sorted first and stated in full, and reject a thread per request and labels on one stream.
* [Help that teaches keys is a temporary sheet on the prefix, not an always-on column](help-that-teaches-keys-is-a-temporary-sheet-not-a-column.md) - Anything "always on" that exists to teach the keys steals the width the content needs; in a keyboard-first client the help panel is off by default and opens as a small temporary sheet on the prefix key, and the human reversed an always-on help column in one comment round.
* [Inventory spawn routes before specifying a feature](inventory-spawn-routes-before-specifying-a-feature.md) - Before specifying a spawn feature, enumerate each execution route and record its option handling, authoritative feature gate, older-side behavior and verification rather than treating one dialog as one implementation.
* [Plan dependent soul text to land with or after its capability pin](soul-text-lands-with-its-capability-pin.md) - When soul text relies on a package capability change, record the pin dependency in the plan and soul PR rather than treating two text changes as independent landings.
* [Condensing instructions must preserve load coverage and deliberate text contracts](condensing-instructions-preserves-load-triggers.md) - Map text consumers before setting a compression target, preserve deliberate wording contracts and skill load triggers, and have an independent reader per capability compare the complete original.
* [Check human briefs, proposed choices and doc-review statements against the lane's decisions](ask-for-the-record-of-the-briefs-subject-before-designing.md) - Check the lane's records before designing or treating review remarks as facts, resume parked direction, route supersessions to the deciding human with citation, reason and loss even under delegated review, distinguish decisions from leanings or questions, and publish drafts where their readers can open them.
* [A cross-client redesign starts with a classified feature inventory and one shared design that each client renders](inventory-then-one-shared-design-for-a-cross-client-redesign.md) - Before drawing anything for two clients, inventory every feature of the existing clients and classify each as essential, useful, nice-to-have or internal plumbing; derive one design from the human's questions and have each client's proposal render that same design, so parity is a ledger and comments on either apply to both; when the proposals become one interactive prototype, both renderers draw only from shared selectors and the build asserts no cut words and the keyboard model in both frames.
* [A framework request is about ergonomics, not rendering architecture; separate a terminal client's chrome from its live agent pane](framework-request-is-ergonomics-separate-chrome-from-live-pane.md) - A human's "build it with Ink" asks for Claude-Code-like ergonomics, not a renderer; a React-style terminal framework can carry a client's chrome but rebuilds the whole grid per frame, so a live agent pane needs an in-process terminal emulator whatever the chrome, and the honest proposal measures the frame floor and names the gating spikes and packaging decisions instead of promising fidelity.
* [When changing a shared layer, enumerate the guarantees the old behaviour held up](enumerate-what-a-removed-behaviour-held-up.md) - Before removing shared behaviour, lifting a refusal or allowing unilateral state changes, inventory the affected paths and guarantees beyond the changed code's callers, assign each a disposition, and verify what no longer holds by construction.
* [Design records and release notes name no hosts, people, paths or personal repositories](design-records-name-no-deployment-specifics.md) - Deployment specifics drift into a spec when its author reads the live deployment for facts; before hand-over, search the record for host names, the human's name, absolute paths and personal forge owners and replace them with neutral examples and "a pattern one deployment uses".
* [When the present human is the operator, run a TTY-free one-liner they ask for and report, instead of handing it back](run-tty-free-one-liners-for-the-present-operator.md) - A skill that says an act "is the operator's" draws a line of authority, not of hands; when the human in the session is that operator and has asked for an act that needs no TTY, password or secret, run it and say so, or ask once and act on the answer, rather than handing it back repeatedly.
* [Trace each "done" item to the code that owns it before accepting the task's repository list](trace-done-items-to-owning-code-before-accepting-repo-list.md) - Before a cross-area spec adopts the brief's repository list, open the code that produces each promised outcome today and name its repository, owner, function or command and version; a dependency outside the named repositories goes to the maintainer before building.
* [A custody question the human refuses in the system's vocabulary is a design signal, not an input to collect](human-refusal-of-a-custody-question-is-design-direction.md) - When a brief tells the lead to ask the human which identity is theirs or where a key should live and the human declines the question itself, take the refusal as direction: decide the mechanics with the domain experts and the maintainer, make the concept invisible in the product, and let the human review behaviour only.
* [Check who never reaches a registry's writers](registry-population-needs-user-path-coverage.md) - Before fixing a per-user registry's writer set, check that CLI-only, client-only and pre-existing users reach it, and weigh automatic population by its steady-state cost and preservation of explicit removal.
* [Automatic per-user writes need runner isolation in the same change](automatic-per-user-writes-need-runner-isolation.md) - When ordinary commands gain a per-user write side effect, plan runner isolation, a personal-file mutation guard, eligible positive fixtures and interruption cleanup in the same change rather than discovering them in CI.
* [Interim docs create migration inputs for the later command](interim-docs-create-migration-inputs.md) - When interim docs teach a manual artifact that a later command will manage, name those copies in the command spec, justify adoption or refusal from their authorship and ownership, and plan the migration text with the command's docs follow-up.
* [Outliving a client requires independent output, not only no signals](outliving-a-client-needs-independent-output.md) - A lifecycle change promised to outlive its client needs output destinations independent of that client's readers, because detachment and a no-signal policy alone leave a broken-pipe failure path.
* [Real-terminal waits must prove the state they observe](real-terminal-waits-prove-the-observed-state.md) - Before trusting a real-terminal content or absence check, establish the intended view and fixture state, account for capture transformations, and wait for a closing transition before sending the next key.
* [Verify host-bound fixes on the reproducing host](verify-host-bound-fixes-on-the-reproducing-host.md) - When the fixing host lacks the runtime that exposes a bug, obtain exact-head evidence on the reproducing host using the same minimal repro and a no-fix control, with harness failures reported separately.
* [Check the affected-test inventory, not only the green runs](check-affected-test-inventory-at-handback.md) - Brief and check the affected-test inventory by changed surface and transition, with results or explicit gaps and evidence that gated behavior ran on a feature-enabled integration tree.
* [The lead checks user-facing claims against evidence, not just reviewed wording](recheck-dictated-words-against-the-build.md) - Test interaction claims before handover, propagate corrections to every consumer, and finish a fresh-context claim review of human-polished public docs against a pinned tree before the PR.
* [Compare a code-reading leaning with alternatives before specifying it](compare-a-leaning-with-alternatives-before-specifying.md) - Before a risky implementation assumption becomes a spec, compare the lead's preferred approach with plausible alternatives under the same state-preservation and interruption checks.
* [Send a relay's own reading to the maintainer before offering a remedy](relay-own-readings-through-the-maintainer.md) - Submit a relay's own remedy to the maintainer first, then preserve the accepted answer's wording and attribution without adding fix-version promises or making general setup advice host-specific.
* [Date host-read facts before a cross-workspace adoption gate](date-host-read-facts-before-an-adoption-gate.md) - Before a version-dependent adoption gate, enumerate the adopter's hosts from team presence and require each version to be read on the named host with its observation time and reporting route.
* [A passing composition does not prove every copied input is needed](prove-copied-inputs-are-needed.md) - Before requiring a second client to retain state copied from the first, compare its composition with and without each candidate input and establish which consumer path actually needs it.
* [Run the consumer spec against the built producer before handover](run-consumer-spec-against-built-producer.md) - When a consumer spec predates its shared producer, exercise its compositions against the built code before handing it to the developer; matching names does not establish matching behavior.
* [Establish the cause before changing a restore-test baseline](control-before-changing-a-restore-baseline.md) - Before changing what a restore test compares against to cure a platform-specific failure, use controls to distinguish the program's effect from the harness or environment's effect.
* [Inspect the producer before making a client limitation a permanent exception](inspect-the-producer-before-making-an-exception-permanent.md) - Before declaring a rule exception permanent because a client lacks provenance, inspect the producer that combines the sources and determine whether it can preserve the distinction.
* [Review shared-client prerequisites with their owner before depending on them](import-closure-needs-owner-review.md) - Review shared modules and callers with their owner before estimating a second client, then isolate and test small shared prerequisites for owner review at an exact commit before building their consumers.
* [Test feasibility before committing to a plan](test-feasibility-before-choosing-between-owners.md) - Use bounded, authorized CI spikes to settle feasibility disagreements and recheck inherited limitations before planning hardware, rental or recurring manual work around them.
