# Lessons

What administering a workspace's configuration taught: misrouted changes, misleading answers, and what verification caught.

* [A host-wide pi model is one `launch set` write](a-host-wide-pi-model-is-one-launch-set-write.md) - A machine-wide harness-and-model choice is a `souls.launch` host fact written by `oats soul launch set`, not a PR, launch-config or hand edit; resolve the nickname to pi's `provider/model-id` first and verify with spawn previews.
* [Diagnose "no harvests lately" from the base and the pin history](diagnose-missing-harvests-from-the-base-and-the-pin-history.md) - When asked why knowledge harvests stopped, count the base's `okf-harvest/*` PRs by date, line the drop up with the oats.okf pin history, and read the captured harvest instructions for host-dependent gates before auditing live instances; a provider fix reaches a home only on respawn, so the PR count recovers after respawns.
