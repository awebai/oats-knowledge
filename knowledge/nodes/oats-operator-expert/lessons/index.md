# Lessons

Placement, identity and verification judgement learned operating deployments across machines.

* [Place each fact at the scope that owns it — organisation-wide in the workspace, host facts in the uncommitted local file, single-holder facts at spawn — and let meaning, not type, break ties](place-each-fact-at-the-scope-that-owns-it.md) - Three legal surfaces accept configuration facts; the docs say what each accepts, not which one a fact belongs to. Choose by blast radius: who else would this fact reach here?
* [Configure against what the installed provider reads, not the grammar the kernel accepts or previews — and keep declared intent the provider does not yet honour](the-installed-provider-is-the-authority-for-a-setting.md) - A setting takes effect only if the shipped provider's reader consumes it; the kernel's payload model and preview are a writer's view, so verify by provider behaviour, and keep declared per-team intent in the workspace file while obtaining the effect by placement.
* [The messaging root is a deployment-bounded host fact: where it sits decides which team residents mint into, and a root above the deployment is a silent cross-team leak](messaging-root-placement-decides-the-team.md) - Placement of the messaging root inside the deployment boundary, not configuration text, decides which team a freshly minted resident joins; one root per deployment, pinned and verified per certificate.
* [Retire ordering for self-custodial identities: de-register from inside the home before removing it, and treat stranded-record cleanup as a deferred re-check](self-custodial-identity-retires-from-inside-the-home.md) - When an instance's external identity key lives in its home, retire by stopping the runtime, self-deleting the identity from inside the home, then removing the directory; a skipped step leaves a liveness-guarded stranded record that is cleaned by one scheduled re-check, not a retry loop.
* [A soul served through a shared checkout is only as current as that tree — validity is not currency, and repair belongs to the tree's owner](shared-checkout-serves-a-stale-soul.md) - A repository-resident soul read through a shared checkout gives a coherent but possibly stale bundle that nothing flags; verify the tree against the remote before trusting it, and leave repair to the tree's owner.
