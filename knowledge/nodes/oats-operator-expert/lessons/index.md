# Lessons

Placement, identity and verification judgement learned operating deployments across machines.

* [Place each fact at the scope that owns it — organisation-wide in the workspace, host facts in the uncommitted local file, single-holder facts at spawn — and let meaning, not type, break ties](place-each-fact-at-the-scope-that-owns-it.md) - Three legal surfaces accept configuration facts; the docs say what each accepts, not which one a fact belongs to. Choose by blast radius: who else would this fact reach here?
* [Configure against what the installed provider reads, not the grammar the kernel accepts or previews — and keep declared intent the provider does not yet honour](the-installed-provider-is-the-authority-for-a-setting.md) - A setting takes effect only if the shipped provider's reader consumes it; the kernel's payload model and preview are a writer's view, so verify by provider behaviour, and keep declared per-team intent in the workspace file while obtaining the effect by placement.
* [The messaging root is a deployment-bounded host fact: where it sits decides which team residents mint into, and a root above the deployment is a silent cross-team leak](messaging-root-placement-decides-the-team.md) - Placement of the messaging root inside the deployment boundary, not configuration text, decides which team a freshly minted resident joins; one root per deployment, pinned and verified per certificate.
* [Retire ordering for self-custodial identities: de-register from inside the home before removing it, and treat stranded-record cleanup as a deferred re-check](self-custodial-identity-retires-from-inside-the-home.md) - When an instance's external identity key lives in its home, retire by stopping the runtime, self-deleting the identity from inside the home, then removing the directory; a skipped step leaves a liveness-guarded stranded record that is cleaned by one scheduled re-check, not a retry loop.
* [A soul served through a shared checkout is only as current as that tree — validity is not currency, and repair belongs to the tree's owner](shared-checkout-serves-a-stale-soul.md) - A repository-resident soul read through a shared checkout gives a coherent but possibly stale bundle that nothing flags; verify the tree against the remote before trusting it, and leave repair to the tree's owner.
* [A team-local identity is reachable only inside its team — a seat that other teams must contact needs a global identity served from custody](a-team-local-identity-is-reachable-only-inside-its-team.md) - Choose the identity kind by who must reach the seat first: team-local for workers, a custody-served resident for any seat other teams or outside parties must find; never a per-instance global mint or copied keys.
* [Harvested knowledge on an unpushed main never leaves the machine](harvested-knowledge-on-an-unpushed-main-never-leaves-the-machine.md) - When the soul lives in the repository and the instance does not own main pushes, harvest delivery must be a branch and a pull request; a local main ahead of the remote strands knowledge with no failure signal.
* [A channel's verified=false is the channel's verdict; confirm with a CLI fetch before suspecting the sender](a-channel-verification-flag-is-the-channels-verdict-not-the-senders.md) - The push channel and the CLI verify a message independently and can disagree; when the CLI fetch says verified and the registry mapping is consistent, the failure is channel-local state and the sender should not rotate anything.
* [A loop variable named path empties the search path in zsh](a-shell-variable-named-path-empties-the-search-path.md) - In zsh the lowercase array path is tied to PATH, so assigning a plain string to a variable called path inside a loop makes every subsequent command in that shell unresolvable; the loop then prints its own success messages while nothing ran.
* [A new execution route that publishes resolutions may still be unable to scaffold the work targets standing seats use](captured-route-scaffolds-only-directory-work-mode.md) - Before recommending a migration onto a new execution route, verify which work targets it can scaffold and whether it can wake and retire an instance; a route that publishes and launches only directory-mode homes cannot host workspace, worktree or checkout seats yet.
* [A roster command run against a linked Git worktree can resolve its agents root to the main checkout](status-on-a-linked-worktree-resolves-to-the-main-checkout.md) - When a directory flag points at a linked worktree, roster listing followed the repository's common Git directory to the main checkout's agents root while composition preview used the worktree itself; verify which root a command reports before reading its output as the worktree's state.
