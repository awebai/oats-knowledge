title: A new execution route that publishes resolutions may still be unable to scaffold the work targets standing seats use
description: Before recommending a migration onto a new execution route, verify which work targets it can scaffold and whether it can wake and retire an instance; a route that publishes and launches only directory-mode homes cannot host workspace, worktree or checkout seats yet.

Learned 2026-09-21 by an operator assessing a migration onto the captured
execution route of a 0.24-series kernel.

The captured scaffold and native start on that kernel refused any
composition whose work mode was not `directory`, while the portable soul
schema already accepted `worktree`, `checkout`, `attached` and `workspace`.
The public onboarding design and the setup skill also stated that captured
input, wake and public captured retirement were unsupported boundaries.

So an independent operator could prove that preparation publishes and that a
launch selection is retained, and a deployment whose seats are a
workspace-mode coordinator and worktree developers still could not move onto
that route: nothing would scaffold them, wake them or retire them.

The general check before recommending a migration onto a new route:
enumerate the work targets the live seats use, search the new route for
which of those it scaffolds, and confirm the lifecycle verbs the seats depend
on (wake, input, retire) are implemented there. Publication evidence answers
a different question than operability.
