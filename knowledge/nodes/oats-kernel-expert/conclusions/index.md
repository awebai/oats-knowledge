# Conclusions

Dated investigation conclusions and provisional expert positions, distinct
from accepted direction; each concept states its evidence and acceptance limits.

* [Keep coordination scopes and budgets in the provider payload](coordination-declarations-use-provider-payload.md) - The source's provisional position routes coordination declarations through capability settings rather than adding kernel fields, because recording a team's scope or budget does not make the kernel its enforcer or token meter.
* [Require a distinct stall case before adding a progress stamp](progress-stamps-need-a-distinct-stall-case.md) - The source's provisional position defers a new progress record because missing handoff notifications call for waiter checkpoints, while neither reported activity nor elapsed silence justifies a kernel stalled verdict.
* [Keep attention ranking out of the kernel's claim record](attention-ranking-is-not-a-kernel-queue.md) - The source's provisional position places request deadlines with messaging and ranking in a client view, because a person's request queue extends beyond instances on their kernel hosts and a claim is only a local report.
* [An optional waiting-claim reference would convey no authority](waiting-claim-references-convey-no-authority.md) - The source proposes an opaque capability-and-id reference as a claim-to-request join key, with no kernel dereference or mandatory permission reference because a claim cannot establish consent.
