# Decisions

* [Home process scans state their visibility limit instead of refusing on every unreadable process](home-process-scan-has-an-explicit-visibility-limit.md) - A home-wide process scan accepts a documented inspection blind spot because rejecting unreadable processes would prevent ordinary lifecycle work, while failure of the scan itself remains unknown.

* [Keep kernel responsibilities generic and capability runtimes complete](kernel-and-capability-responsibility.md) - The kernel resolves, copies and runs the lifecycle through generic seams; capabilities own concrete behaviour, including operating on OATS.
* [Soul declares identity and where its capabilities come from; the workspace versions; the host supplies facts](soul-declares-kind-config-assigns-policy.md) - Location in the soul, versions in the workspace, host and spawn facts in their own homes; packages never carry deployment policy.
* [Integrity, origin and consent are different proofs](trust-approval-and-consent-boundaries.md) - Membership and declaration are trust; the lock proves contained reproducible bytes; host-install consent is separate.
* [Capability resources must outlive package staging](contained-capability-lifetime.md) - An explicit payload boundary and a complete contained copy keep staging and neighbouring paths from becoming runtime authority.
* [Compatibility follows supported adoption, not every intermediate format](evidence-bounded-compatibility-and-migration.md) - Supported adoption bounds compatibility, unrepresentable migrations refuse, and manifest floors remain explicit with a narrow non-required-hook exception from 0.49.0.
* [Unknown hook events are forward-tolerant unless required](forward-tolerant-hook-events.md) - Non-required hook events may be skipped to preserve capability composition, but required events still refuse and the tolerance starts only at OATS 0.49.0.
* [Worktree setup is a capability hook, not a repository-file contract](worktree-setup-is-a-capability-hook.md) - A composed capability decides what repository setup runs, avoiding a second kernel trust mechanism based on a file's presence, host opt-in or script scanning.
* [Harnesses start natively; OATS contributes skills and instructions and sandboxes nothing](harness-native-launch.md) - The strict-curriculum target was retired for every harness; bypass flags only on explicit yolo opt-in.
* [Harness authentication is native and user-managed; OATS never handles credentials](harness-native-authentication.md) - OATS launches the harness in its own authenticated context and never parses, copies, stores or wraps credentials.
* [Kernel supplies provider-neutral messaging inputs; the capability owns identity, membership, transport and qualification](messaging-capability-owns-provider-behaviour.md) - Generic payload, identity and team inputs from the kernel; identities, teams, delivery and readiness from the capability.
* [Separate operational home from granted work authority](home-work-authority.md) - Lifecycle identity stays outside disposable work, so work topology never becomes operational or knowledge authority.
* [Live lineage is deliberately bounded](bounded-live-lineage.md) - Sparse explicit relations favour truthful ambiguity refusal over a permanent history or multi-file transaction promise.
* [Preserve recovery authority until the outcome is proven](preserve-authority-until-cleanup-is-proven.md) - Partial failures retain the identity and obligations a retry needs; recovery derives truth from the object.
* [Retire Git reads preserve the spawn baseline's configuration semantics](retire-git-reads-preserve-baseline-semantics.md) - Retire keeps operator global and system Git configuration to remain comparable with the spawn baseline, so its read profile must not be unified with fully isolated observation without an explicit baseline transition.
* [Recovery copies preserve work, not repository-local Git behavior](recovery-copies-do-not-inherit-local-git-config.md) - Nested-repository recovery deliberately omits local Git configuration beyond status semantics, rather than reinstalling agent-selected executable behavior for a later operator.
* [Record locks favor recoverable refusal over live-holder theft](record-lock-liveness-tradeoff.md) - Lock age never overrides a live local holder; the foreign-lock fallback and check-unlink race stay explicit limits.
* [A minimal process boundary avoids permanent private coupling](minimal-process-boundary.md) - A structured public CLI lets independent consumers evolve without freezing private kernel functions.
* [Configured scope is not messaging membership](configured-team-boundary.md) - A declared configuration boundary establishes team scope independently of ambient messaging identity.
