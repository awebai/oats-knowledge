# Stewardship

How the OATS project ships: judgement only, each concept with an owner and an
update-on-change rule; procedures live in the oats-expert soul's skills.

* [Presentation features reuse one state contract unless divergence is justified](presentation-features-reuse-one-contract.md) - Review new instance-presentation features against the established state and mutation boundaries, requiring a reason for divergence so display choices do not acquire identity, policy or lifecycle meaning.
* [Coordination policy lives in capabilities, not in the kernel or oats.core](coordination-policy-lives-in-capabilities.md) - Review keeps team coordination policy out of neutral lifecycle mechanisms; OATS delegates finished-worker retirement to experts and lane maintainers without a fresh human request, through its composed capabilities.
* [How the OATS project ships and reviews](review-protocol.md) - Maintainer review binds verdicts to content and issue-recorded contract decisions, preserves same-area integration evidence, requires timely and safely obtained verification, uses fresh and second readers, checks hand-written release claims, and judges tests against requirements rather than implementations.
* [One release lane does the final review, merge and tags; project lanes are defined by their own maintainers](release-lane-and-project-lanes.md) - One release lane owns final review, merge and tags; project maintainers define lanes without sign-off, route follow-ups by the map, review with one second reader, record changed practice and hand over approved heads, while the directing human's lanes launch routine filed work without asking again; child overflow seats add execution capacity without a second accountable authority.
* [Release judgement for the tag-driven lane](release-traps.md) - Release judgment distinguishes publication from artifact availability, rehearses released-state upgrades, changed macOS tests and newly taught skill commands before tags, contains failed-tag repairs, separates one-off package patches from maintenance lines, gates package-soul adoption through catalog, explicit-tag and shared-workspace routes, and coordinates source, tag, mirror, every form of version pin and the framework release that carries them, and pairs changes to shared instructional behaviour across separately released packages.
* [Cross-workstream delivery: freeze the contract first, adopt then adapt, prove the merge](multi-workstream-delivery.md) - Freeze shared contracts before implementation, adopt then adapt sibling suites, and prove merge fidelity; ship-together sets need whole-set evidence before the first merge or an explicit release hold, and a paused shared-package contract stage is reverted before release.
