# Stewardship

How the OATS project ships: judgement only, each concept with an owner and an
update-on-change rule; procedures live in the oats-expert soul's skills.

* [Presentation features reuse one state contract unless divergence is justified](presentation-features-reuse-one-contract.md) - Review new instance-presentation features against the established state and mutation boundaries, requiring a reason for divergence so display choices do not acquire identity, policy or lifecycle meaning.
* [Coordination policy lives in capabilities, not in the kernel or oats.core](coordination-policy-lives-in-capabilities.md) - Review separates neutral lifecycle mechanisms from team coordination policy, including when to retire children, and keeps core authority wording from contradicting a composed capability.
* [How the OATS project ships and reviews](review-protocol.md) - Maintainer review binds verdicts to content and recorded decisions, preserves same-area integration evidence inside merge batches, requires timely, safely obtained verification, uses fresh and second readers, and judges tests against requirements rather than implementations.
* [One release lane does the final review, merge and tags; project lanes are defined by their own maintainers](release-lane-and-project-lanes.md) - Besides the single release lane, every lane is a project lane that a maintainer defines on the lane map when its human's work needs it, with no sign-off; inside it the maintainer launches, reviews and names one second reader, and hands approved heads to the release lane.
* [Release judgement for the tag-driven lane](release-traps.md) - Release judgment distinguishes publication from artifact availability, rehearses upgrades from released state and changed macOS tests before tags, contains failed-tag repairs, gates a package soul's new key on an installed accepting kernel, and coordinates source, tag, mirror and every form of version pin.
* [Cross-workstream delivery: freeze the contract first, adopt then adapt, prove the merge](multi-workstream-delivery.md) - Freeze shared contracts before implementation, adopt then adapt sibling suites, and prove merge fidelity; ship-together sets need whole-set evidence before the first merge or an explicit release hold, and a paused shared-package contract stage is reverted before release.
