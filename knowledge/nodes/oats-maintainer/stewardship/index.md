# Stewardship

How the OATS project ships: judgement only, each concept with an owner and an
update-on-change rule; procedures live in the oats-expert soul's skills.

* [How the OATS project ships and reviews](review-protocol.md) - Maintainer review binds verdicts to content and recorded decisions, preserves same-area integration evidence inside merge batches, requires timely, safely obtained verification, uses fresh and second readers, and judges tests against requirements rather than implementations.
* [One release lane does the final review, merge and tags; project lanes are defined by their own maintainers](release-lane-and-project-lanes.md) - One release lane owns final review, merge and tags; maintainers define project lanes without sign-off and hand over approved heads, while child overflow seats add execution capacity without a second accountable authority.
* [Release judgement for the tag-driven lane](release-traps.md) - Release judgment distinguishes publication from artifact availability, rehearses upgrades from released state, coordinates source, tag, mirror and pins, and pairs changes to shared instructional behaviour across separately released packages.
* [Cross-workstream delivery: freeze the contract first, adopt then adapt, prove the merge](multi-workstream-delivery.md) - Freeze shared contracts before implementation, adopt then adapt sibling suites, and prove merge fidelity; ship-together sets need whole-set evidence before the first merge or an explicit release hold, and a paused shared-package contract stage is reverted before release.
